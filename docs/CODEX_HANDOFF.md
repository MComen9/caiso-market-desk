# Codex 接手说明

## 1. 项目目标与交接范围

用户希望将 CAISO 平台、研究内容和数据交给团队长期使用，并在 Codex 中继续开发。仓库承载源码、结构化说明、模型与数据版本；公开网站承载浏览与下载。

本次迁移的核心验收是：代码可接手、公开数据不丢失、现有结果可复现、网站可访问、远端状态可验证。迁移本身不代表重新训练模型、更新市场数据或获得新的预测业绩。

## 3. 目录与运行边界

| 目录 | 职责 | 接手时注意 |
| --- | --- | --- |
| `apps/viewer/` | 公开只读交互平台 | 不调用原站私有 API，不含数据库写入或账户配置入口 |
| `apps/workbench/` | 完整工作台源码、服务端接口及研究工作 | 需要自己的运行环境；源码公开不表示服务端已部署 |
| `apps/workbench/research/` | 数据处理、选型、预测和模拟脚本 | 先阅读具体 CLI；不要自动运行历史下载或完整训练 |
| `data/published/` | 已公开数据、报告和附件 | 按原版本保留内容与清单；不混入私有实验记录 |
| `data/downloads/` | 补充离线交付附件 | 下载入口与发行说明同步维护 |
| `docs/` | 团队知识与开发说明 | 修改功能、口径和部署方式时同步更新 |
| `scripts/` | 项目级安装与验证辅助程序 | 以实际文件和根 README 为准 |

默认只安装公开前端依赖，使用 Python 标准库重放冻结模拟；研究训练依赖和工作台的 JavaScript 依赖按需安装。安装与构建不应自动抓外部数据、重训模型、写入线上数据库或触发部署。

### 项目级命令

从仓库根目录执行：

```bash
# 默认 Codex 环境准备：安装查看版依赖、构建、验证公开数据及冻结 V4。
bash scripts/codex-setup.sh

# 只有任务需要训练依赖时才追加；不执行训练。
bash scripts/codex-setup.sh --research

# 只有任务涉及完整工作台时才追加；不初始化运行数据库。
bash scripts/codex-setup.sh --workbench
```

脚本默认依次执行 `npm run setup`、`npm run build`、`npm run verify`。研究依赖安装到仓库内 `.venv`，从 `apps/workbench/research/requirements.txt` 读取。可选工作台流程安装其锁定依赖并运行类型、回归和构建检查。两项可选参数可以组合使用。

日常开发使用 `npm run dev`；本地发行包使用 `npm run package`。这些命令不会创建 GitHub 仓库、配置 Pages 或发布 Codex 环境。

本次迁移已经完整运行默认安装脚本：公开查看版构建成功，221 项公开数据与清单一致，冻结 V4 前向及开发窗口的两组模拟关键字段与原结果完全相同。工作台代理也单独验证了安装、类型、回归和构建命令。`--research` 训练依赖安装不是本轮默认验收项，不能据此称每个可选流程都已在新的 Codex Cloud 环境中运行过。

## 4. 已冻结的 V4 研究基线

### 4.1 版本与预测目标

| 项目 | 已有版本的记录 |
| --- | --- |
| 模型版本 | `caiso-current-data-4.0.0+99bd6a8751fe` |
| 公开数据快照 | `caiso-public-2026-11-02`；`data/manifest.json` 收录 221 个文件，共 157,016,050 字节 |
| 生成时间 | `2026-10-30T08:34:02.166Z` |
| 预测目标 | `2026-10-31`，美国太平洋时区 PT |
| 枢纽 | NP15、SP15、ZP26 |
| 点数 | 该目标日 3 × 24，共 72 个节点小时；此计数只适用于该日 |
| 输入历史 | 2025-10-29—2026-10-29，366 天、26,352 个节点小时 |
| 未来实际值 | `actualDa`、`actualFmm`、`actualSpread` 均为空 |

当前网页展示的是归档研究结果。将项目换到 GitHub 或 Codex 不会使上述预测自动变成当前日期的预测。

### 4.2 模型选择

- 在 8 个固定候选中，DA 选择 `ridge_all`，Ridge α=100。
- 价差选择 `shrink14`：14 天同小时价差中位数乘以 0.5。
- FMM 没有独立训练模型，按 `predictedFmm = predictedDa + predictedSpread` 派生。
- 主要特征为价格与价差的 D−2、D−3、D−7、D−14、D−28 滞后、滚动统计、跨枢纽信息和日历。
- EIA、气象、检修等补充资料不能仅因被收录在数据中心，就被写成已用于 V4 训练。

既有价格统计模型学习的是市场机制留下的规律。它没有识别天然气、净负荷或输电等因素的因果贡献比例。

### 4.3 评估划分

| 区段 | 日期与用途 |
| --- | --- |
| 选型验证 | 2026-07-22—2026-09-01，共 42 天 |
| 隔离日 | 2026-09-02 |
| 区间校准 | 2026-09-03—2026-09-30，共 28 天 |
| 隔离日 | 2026-10-01 |
| 开发评估 | 2026-10-02—2026-10-29，共 28 天、2,016 个节点小时 |

最后一个窗口已被查看和用于开发诊断，不能改称“全新独立测试集”。未来研究应新增时间上真正后续的评估窗口，并保存预测生成时可获得的数据版本。

### 4.4 开发评估指标

单位为美元/MWh；下表是原报告与已做只读复核的基线。

| 目标 | 当前 MAE | 基线 MAE | 当前 RMSE | MAE 相对改善 |
| --- | ---: | ---: | ---: | ---: |
| DA | 10.22450 | 11.82574 | 17.11027 | 约 13.54% |
| 价差 FMM−DA | 9.18872 | 9.42685 | 13.72210 | 约 2.53% |
| 派生 FMM | 12.21916 | 13.01625 | 18.24236 | 约 6.12% |

DA 基线为 14 日同小时 DA 均值，价差基线为零价差；派生 FMM 的基线为两者相加。FMM 误差属于从已有输出补充计算的诊断，不是原始独立模型选型指标。

价差方向准确率为 57.84%。该窗口实际负价差占 55.85%，因此比“始终预测负价差”的事后参考只高约 1.98 个百分点；该参考不是后来补入选型的模型。不要只拿 50% 作对照而宣称强方向优势。

名义 80% 区间的实际覆盖率为 DA 74.55%、价差 68.65%，存在覆盖不足。FMM 没有单独校准的区间，不能随意由两个区间相加后称为已校准 FMM 区间。

### 4.5 模拟结果与限制

既有情景使用每模拟成交 MWh 1 美元的固定费用。28 天开发窗口的模拟损益约 397.010311 美元，最大回撤约 291.975624 美元，模拟成交量约 138.28638 MWh，共 88 笔交易。

这不是实际交易记录，也不是全部 CAISO 结算项目的实现。未来计划为 0 笔，未分配预算为 12 MWh；不能为了让页面“有交易”而强行填入信号。前向状态为 `forecast_only`，实际损益为空。

此前独立解压 V4 发行包后，按包内 README 执行前向与开发窗口模拟，已能复现 `day`、`backtest`、`config`、`inputDigest` 和 `forecastGeneratedAt`。迁移后应再次按当前路径验证这条链路；不要直接沿用原机器临时目录。

## 5. 必须保留的业务决策

1. **不采购数据。** 能免费取得且当前可实现的资料可以使用；补不到的字段收敛为明确限制，当前预测不等待它们。
2. **原始证据与模型输入分开。** 已下载、可展示、可用于研究和实际入模是不同状态。
3. **版本冻结。** V1—V4 历史包和报告可供审阅；新实验另建版本。经过公开整理的包应明确标记，不能冒充未经修改的原始完整包。
4. **只读分享与可写工作台分开。** 团队浏览共享版不应访问原数据库或消耗原服务端第三方账户额度。
5. **公开分享已获用户授权。** 公开范围为经过审查的项目内容和数据；原账户凭据、访问令牌、私有实验记录不随迁移发布。
6. **不要只改局部。** 功能改动要核查术语、导航、数据口径、下载内容、报告和文档的一致性。

### 相关市场口径

以下是本项目此前已核实并采用的业务解释。规则存在时效性，后续改变算法或结算逻辑时应再次核对适用版本。

| 主题 | 已采用的口径 | 对代码与解释的影响 |
| --- | --- | --- |
| 2026 年 LMP | `MEC + MCC + MCL + MCG`，共四分量；MEC 在同一 BAA 内相同 | 不再沿用“全西部唯一能量价＋拥塞＋损耗”的三分量描述 |
| 市场时间层级 | DA 为小时，FMM 为 15 分钟，RTD 为 5 分钟 | 读取、聚合和建模时明确市场与粒度 |
| 虚拟交易能量平仓 | 按该小时四个 FMM LMP 的简单平均；并有其他结算项 | 当前 FMM−DA 目标有能量口径依据，但固定费用模拟不能称完整结算 |
| 净负荷展示 | Today’s Outlook 的 system demand−wind−solar 不含可调度抽蓄负荷和电池充电 | 不将该曲线直接当作完整的发电侧平衡需求 |
| 价格水平与 DA/FMM 价差 | 前者看可交付供需和边际资源；后者更看相对日前预期发生的变化 | 高实时负荷不自动意味着 FMM 高于 DA；特征解释不等于已识别因果比例 |

官方依据：[Appendix C（2026-05-01）](https://www.caiso.com/documents/appendix-c-locational-marginal-price-as-of-may-1-2026.pdf)、[Section 11（2026-07-22）](https://www.caiso.com/documents/section-11-california-iso-settlements-and-billing-as-of-jul-22-2026.pdf)、[Today’s Outlook](https://www.caiso.com/todays-outlook)。

## 7. Codex Cloud 环境配置

根据 2026-11-05 核实的官方文档，配置方式为：

1. 打开新任务的 `Work in → Cloud → Select environment → Create environment`，或 `Settings → Codex Cloud → Environments → Create environment`。
2. 选择实际创建完成的 CAISO GitHub 仓库；按界面完成所需连接。
3. 让 Codex 读取本仓库，以 `bash scripts/codex-setup.sh` 准备默认依赖和验证结果；按任务需要选用额外安装参数。
4. 检查安装与测试报告，保存并 `Publish`；看到 `Environment published` 后再启动第一个任务。

仓库中的安装脚本帮助环境准备，但不能替代实际账号中环境的创建、发布与访问验证。在取得环境发布和首任务运行证据前，迁移状态保持未完成；通过有权限的界面或工具完成后再更新记录。

网站公开访问、GitHub 仓库协作权限、Codex 环境使用权限是三个独立设置。不要假定团队能打开网站就能使用同一个 Codex 环境，也不要为了共享环境而公开个人凭据。

首轮只需依赖安装与已归档数据，不需要配置付费数据密钥。网络权限按实际安装所需域名配置；后续需要官方数据采集时另按具体任务设置，不默认开放全部互联网。
